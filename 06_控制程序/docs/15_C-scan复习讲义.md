## 1 整条信号链（一张图）

```
NI PCIe-6323（Dev1，BNC-2110 引出）
 ├─ P0.0 / P0.1 ──→ SR2(X) STEP− / DIR− ──→ X 滑台（0.5 µm/脉冲，DIR 1 = 朝电机）
 ├─ P0.2 / P0.3 ──→ SR2(Y) STEP− / DIR− ──→ Y 滑台（同上）
 ├─ P0.6 ──→ USER 1 ──┬─→ DG852 背面 CH1 AUX（三通）──短线──→ CH2 AUX
 │                    └─→ PFI3（并线）= ctr1，数 P0.6 发了几个
 └─ P0.7 激光触发（现在一直是 0）

DG852 CH1 = G1 ──三通──┬─→ ATS9462 TRIG IN（50 Ω）   ← ATS 每收到一个就采一条 A-line
                       └─→ 示波器 CH2
DG852 CH2 = G2 ──三通──┬─→ ATS9462 CH A（50 Ω）      ← 假的"光声信号"
                       └─→ 示波器 CH3
示波器 CH1 = P0.6
```

一句话：**电机每走 K 步，P0.6 发一个脉冲 → 发生器吐出 G1（给 ATS 当触发）和 2 µs 后的 G2（假装光声信号）→ ATS 采 1024 点 = 一条 A-line。**

## 2 频率和时间都是怎么定的

你只定**位置相关的两三个数**，其余都是推出来的：

| 量 | 怎么来 | 10 × 10（Δx 10 µm） | B-scan 默认（Δx 5 µm） |
|---|---|---|---|
| 每脉冲走多远 | SR2 拨码 4000 步/转 × 导程 2 mm | 0.5 µm [实测] | 0.5 µm |
| **扫描速度** | C 第 34 行直接设；B = Δx × 触发频率 | 4 mm/s | 5 µm × 800 Hz = 4 mm/s |
| **步频** | 速度 ÷ 0.5 µm | 8000 Hz | 8000 Hz |
| K（每像素几步） | Δx ÷ 0.5 µm | 20 | 10 |
| **触发频率**（每秒 A-line 数） | 步频 ÷ K | 400 Hz | 800 Hz |
| DO 时钟 fs | 步频 × floor(250 k ÷ 步频)：每步正好 31 行，触发间隔才是整数行 | 248 kS/s（实测没被取整） | 248 kS/s |
| P0.6 脉宽 | round(10 µs × fs) = 2 行 | 8.06 µs | 8.06 µs |
| ATS 采样率 / 每条点数 | 180 MS/s × 1024 点 | 5.69 µs 窗口 | 同左 |

要点：
- **触发是按"走了多少步"发的**，不是按时间。所以像素间距一定精确；只有在匀速段，时间间隔才均匀。加速、减速段（各 200 µm）不发触发（计划图上红点只在直线段）。
- **B 和 C 的设置方式不一样**：B 直接设触发频率（第 24 行），速度 = Δx × 触发频率；C 直接设速度（第 34 行），触发频率 = 8000 ÷ K。C 这样写，是为了换 Δx 时步频和 fs 不变，不会超过验证过的 4 mm/s。
- 速度上限 4 mm/s：带加速只验证过 4；不加速直接起步 5 mm/s 会失步（电流只有 0.3 A）。

### 发生器 DG852 两路（docs/13 §2）

| | CH1 = G1（触发） | CH2 = G2（假信号） |
|---|---|---|
| 波形 | Square 100 kHz，2 Vpp，Offset 1 V（0 → 2 V） | Square 2.5 MHz，1 Vpp，Offset 0.5 V（0 → 1 V） |
| Burst | NCycle、1 个周期、外触发（P0.6 上升沿）、Idle Bottom | 同左，**Delay 2 µs** |
| 结果 | 每个 P0.6 → 一个 **5 µs** 高的方波（100 kHz 的半个周期） | G1 之后 2 µs，一个 **200 ns** 的脉冲（2.5 MHz 的半个周期） |
| 为什么 | P0.6 直接推 50 Ω 的 TRIG IN 只剩 2.84 V，边沿也不干净；让发生器重新生成一个干净的 2 V 触发 | 模拟光声信号：2 µs ≈ 水中 3 mm 深度 [条件计算] |

- **Imped = Load**：发生器假定另一头是 50 Ω。另一头真有 50 Ω，量到的就是设定值；开路就翻倍。所以示波器上 CH2 = 2 V、CH3 = 1 V，本身就说明 TRIG IN、CH A 都是 50 Ω。
- 不要 Recall `PAM_bscan`（旧的 1.5 Vpp）；背面三通要插在 **CH1 AUX**，不是 10MHz REF（10/14 上午踩过）。

### ATS 的触发门槛
`triggerLevelCode = 150`，ETR_5V 量程下 (150 − 128)/127 × 5 V ≈ **0.87 V**。G1 是 2 V，留足余量；G1 只有 1 V 时会漏触发（10/9 踩过）。

## 3 示波器怎么看（细节 docs/13 §7）

开工 7 步（docs/13 §7.5）：底栏 2 V / 1 V / 500 mV → D = 0 → 不运行时 CH1 是平线 → CH1 Top 约 4.3–4.5 V → CH2 Top 约 2.0 V、+Wid 5.000 µs → Dly↑1→2 约 550 ns → CH3 Top 约 1.0 V、+Wid 200 ns、在 G1 后约 2 µs。

时间轴（以 P0.6 上升沿为 0）：

```
0        P0.6 上升（示波器触发点）
0.55 µs  G1 上升          ← 发生器外触发的反应时间
2.56 µs  G2 上升          ← G1 + Delay 2 µs
2.76 µs  G2 下降          ← + 200 ns
5.56 µs  G1 下降          ← G1 + 5 µs
8.06 µs  P0.6 下降        ← 2 行 ÷ 248 kS/s（屏幕外）
```

ATS 从 G1 越过 0.87 V 开始计时，所以 ATS 量到的上升沿是 **1.926–1.933 µs**（比 2 µs 早约 70 ns 的固定偏差，来源待确认）。P0.6 → G1 的 550 ns 不进数据。

## 4 B-scan：要改什么、要懂什么

**要改的（都在 B 开头）**

| 行 | 名字 | 默认 | 说明 |
|---|---|---|---|
| 15 | RUN_HARDWARE | false | 跑完一定改回 |
| 18 | SAVE_DATA | false | 存 `bscan_data/` |
| 22 | SCAN_LENGTH_UM | 2000 | B-scan 长度 |
| 23 | DX_UM | 5 | A-line 间距，0.5 µm 的整数倍 |
| 24 | TRIG_RATE_HZ | 800 | 触发频率；速度 = Δx × 它，≤ 4 mm/s |
| 37 | MAX_SPEED_MM_S | 4 | 10/14 从 20 改成 4 |
| 51 | ATS.recordsPerBuffer | 50 | 每个 DMA buffer 几条；Nx 会被凑成它的整数倍（B:64） |

**要懂的**
1. 一次 `readwrite` 输出整张时序表（加速 → 匀速 + 触发 → 减速 → 停 → 回程），MATLAB 在这期间被占住（10/12 说的"卡约 2.3 s"就是这个，不是报错）。
2. **ATS 必须在 readwrite 之前 arm**（BeforeAsyncRead → Post → StartCapture），因为 readwrite 一开始就会发触发。
3. 三个数要对上：ctr1（发了几个 P0.6）= ATS 条数 = 计划条数。ctr1 对、ATS 少 → 查 G1 → TRIG IN；ctr1 也少 → 查时序表或 PFI3。
4. 两张图怎么读：docs/13 §8。

## 5 C-scan：要改什么、要懂什么

**要改的（C 开头）**

| 行 | 名字 | 默认 | 什么时候改 |
|---|---|---|---|
| 20 | RUN_HARDWARE | false | 检查模式对了才改 true，跑完改回 |
| 22 | ATS_ENABLE | true | false = 只动电机（4.1） |
| 24 | SAVE_DATA | false | 要存数据时 true（存 `cscan_data/`） |
| 26 | PAUSE_BETWEEN_ROWS | false | true = 每行前后停，看胶带（会停 2 × NY 次） |
| 27 | Y_CALIBRATED | true | 10/14 标定后改的，别动 |
| 30–33 | NX / NY / DX_UM / DY_UM | 10 / 10 / 10 / 10 | 扫多大：X 每行 = 400 + NX × Δx ≤ 5000 µm，Y = (NY − 1) × Δy ≤ 5000 µm |
| 34 | SCAN_SPEED_MM_S | 4 | 别超过 4 |
| 51–53 | Y 的 µm/脉冲、方向、序列号 | 0.5 / 1 / "243106105" | 10/14 实测，别动 |
| 76 | ATS.recordsPerBuffer | 2 | 每行 buffer 数 = NX ÷ 它；NX 大时（如 200）改 10，让每行 buffer ≤ 64 |
| 77 | ATS.postedBuffers | Inf | Inf = 全部预先交出；数字 = ring buffer 轮流用几个 |

**要懂的（比 B 多出来的 5 件事）**
1. **每行单独 arm**：每行 arm → readwrite 扫这一行 → 取数 → **Abort** → 存盘 → 回程 + Y。行与行之间没有 P0.6，重新 arm 的空档不会漏触发；不 Abort，下一行的 BeforeAsyncRead 就不被接受。
2. **dual-port 一直在用**：AutoDMA = 板卡边采边 DMA 到电脑 buffer。readwrite 卡住 MATLAB 时，数据照样进板载内存 / buffer，所以取 5 个 buffer 只要约 0.05 s。ring buffer 是另一回事（电脑这边 buffer 循环用），10 × 10 用不上。
3. **停止按钮只在行与行之间生效**：readwrite 期间点的，要等到 drawnow 才处理。停了会做完当前行 → 只回程 → 按累计命令位置退回 Y。**不要 Ctrl+C**（不进 catch、不退回）；关掉小窗口也算停止；暂停时按回车要先点命令行窗口（已加 `commandwindow`）。
4. **出错时的顺序**：先 Abort DMA → 读 ctr1（判断是发送端还是接收端的问题）→ 存出错信息 → 只有出错时**没有** readwrite 在跑（位置已知）才自动退回，否则不动、手摇回记号。6.7 拔线就是"位置已知 → 自动退回"。
5. **怎么证明数据排对了**：测试信号下 MAP 本来就均匀，证明不了。要么用假数据（检查模式，每行亮度不同），要么像 6.5 那样关掉一行的信号，看暗线是不是横的、在不在第 3 行。

**每行时间**（6.10 [实测]）：每行 ≈ 1.13 s + NX × 7.4 ms。斜率就是电机时间，和计划一样；截距比计划多约 0.5 s，是两次 readwrite 启动 + arm/取数/存盘的软件开销。
