## 安全（每次上硬件都适用）

- `RUN_HARDWARE = false` 是默认值；每个阶段先跑检查模式，确认后才改 true，跑完改回。
- `LASER_ENABLE = false`；检查模式里 assert P0.7 那一列全是 0。
- **限位没接**（docs/01）。每次开跑前看手轮记号；程序里累计 X、Y 的命令位置，设软件限位（本周 ±5 mm）。B 的 `MAX_TRAVEL_UM` 只限单次扫描。
- **B:37 的 `MAX_SPEED_MM_S = 20` 是手册值，要改成 4。** 带加速只验证过 4 mm/s；不加速 5 mm/s 会失步。（10/13 用户同意：B:37 改成 4，cscan_test 也用 4；由用户自己改。T2:26 也是 20，Y 版建议同样改成 4。）
- 只在**行与行之间**停。`readwrite` 运行中按 Ctrl+C 之后电机停在哪、onCleanup 会不会执行，都没测过（待确认）。
- 出错时的顺序：先 `AlazarAbortAsyncRead` → 保存已完成的行 → 打印 ctr1 → 再决定退不退回。只有 `readwrite` 已经跑完才自动退回；`readwrite` 中途出错，位置未知，不自动移动，用手轮重新归零。
- 台架和 Maria 共用（她的 C-scan 不回 Y 原点）。每次开工重做 0.3（发生器）和 0.4（两轴归零）。
- 收工：`RUN_HARDWARE = false`、SR2 断电、发生器 Output 关。

## 附 A　第一版 10 × 10 的参数 [条件计算]

| 项 | 值 | 来源 / 算式 |
|---|---|---|
| Nx × Ny | 10 × 10 | 07 第 3 周 |
| Δx | 10 µm，K = 20 脉冲/像素 | 0.5 µm/脉冲（docs/01）；B:55-57 要求 K 为整数 |
| TRIG_RATE_HZ | 400 Hz（一般取 4000 / Δx(µm)） | 步频固定 8 kHz = 4 mm/s，fs 固定 248 kS/s，和已验证的配置一样（docs/13 §3.1 的 10 µm / 400 Hz 已测 200/200） |
| fs | 248 kS/s | floor(250k / 8k) = 31 行/步（B:69-71） |
| P0.6 脉宽 | 2 行 = 8.06 µs | B:73 |
| 加速 / 减速 | 各 200 µm（400 脉冲），500 Hz 起步，每段约 0.149 s | B:26-27 |
| 每行 X 行程 | (2×400 + 10×20) × 0.5 = 500 µm；触发点在 200…290 µm | B:65-67 |
| X 回程 | 1000 脉冲，不加速，先 2 mm/s（0.25 s） | 单独一次 readwrite |
| Δy | 10 µm = 20 脉冲（⚠ 前提 Y = 0.5 µm/脉冲） | |
| Y 速度 | 1 mm/s | |
| DIR 建立时间 | 100 µs = 25 行，每张表开头 | B:42；手册 ≥ 50 µs |
| 停稳等待 | 50 ms（真实停稳时间待测） | B:43 |
| samplesPerALine | 1024 点（5.69 µs） | B:46 |
| recordsPerBuffer | **2**：每个 buffer 4096 B，每行 5 个 buffer；400 Hz ÷ 2 = 200 个/s < 2 kHz | 必须整除 Nx；SDK 建议至少 2 个、最好 ≥3 个 buffer（PDF 第 53 页）。B 原来的 50 会把 Nx 凑成 50（B:64） |
| Wait 超时 | 2000 ms | B:303 |

- **时间**：行扫描表约 0.37 s；回程 + Y 约 0.31 s；每行约 0.68 s；10 行全程约 **6.9 s**（下限，未含 readwrite 启动和 ATS arm 的开销）。
- **数据**：只存 uint16 `raw(1024, Nx, Ny)` = 204,800 B。不存 double 电压：3×3 mm 时 uint16 已有 18.4 GB，double 会到 73.7 GB，超过 64 GB 内存。
- **附 A2（量四个角用）**：Δx = Δy = 200 µm（K = 400），TRIG = 20 Hz，步频仍是 8 kHz。每行 X 行程 2400 µm，像素角在 X = 200 µm 和 2000 µm；Y 从第 1 行到第 10 行走 1800 µm。每行约 2.3 s，全程约 25 s。手轮一圈 2 mm，1° ≈ 5.6 µm。

## 附 B　如果行内改成 step-and-settle

- 每个像素 = 走 20 脉冲 @ 8 kHz（2.5 ms，不加速）+ 停稳 t_s + 触发。t_s 先用 1 ms（待测），每像素约 3.5 ms，一行约 35 ms。
- 每个像素都要不加速重新起步，所以速度 ≤ 4 mm/s。时序表要新写，可参照 Maria `C_scan.py:49-55、90-106`。

## 阶段 0　开工检查

**0.1 软件和文件**
- 「在做什么」确认用的是 Research-PAM 里的最新代码，Dev1 和 ATS 没被别的程序占着。
- 「为什么」两张卡同一时间只能给一个程序用；旧文件夹 `PAM_controlProgram\Matlab\bscan_test.m` 是 10/7 的旧版，没有 COUNT_CHECK。

- 失败先查：报 "Hardware is reserved" → `clear dq cnt`，再关 LabVIEW。

**0.2 接线和示波器**
- 「在做什么」按 B-scan 的接法接好 P0.6 → USER 1 → 发生器 AUX → G1 → TRIG IN / G2 → CH A，以及 USER 1 → PFI3。
- 「为什么」触发链和 B-scan 完全一样；10/9 那次"TRIG IN 高阻"的误判，就是示波器 Probe 被设成了 2X。
- 操作：按 docs/13 §1 接线；示波器 CH1–3 都设 Probe 1X；触发选 CH2 或 CH3 上升沿、约 1 V、Normal。
- 通过：运行时 CH1（P0.6）约 4.3 V、宽约 8 µs；CH2（TRIG IN 端）Top 约 1.96 V；CH3 约 1 V、200 ns。
- 失败先查：Probe 倍数；水平位移 D 是否被别人调过。

**0.3 发生器**
- 「在做什么」把 DG852 两路逐项设成 docs/13 §2 的值，再打开输出。
- 「为什么」G1 到 TRIG IN 只有 1.0 V 时会漏触发；设错了，缺行会看起来像程序 bug。
- 操作：逐项核对：
  - CH1：Square 100 kHz、2 Vpp、Offset 1 V、Duty 50%。
  - CH2：Square 2.5 MHz、1 Vpp、Offset 0.5 V、Duty 50%、Delay 2 µs。
  - 两路：Burst NCycle、Cycles 1、Ext Leading、Idle Bottom；Imped Load；**Sync Off、Trig Out Off**。
  - **不要 Recall `PAM_bscan`**：那是 1.5 Vpp 的旧版（10/10 误读时存的）。
  - 先把 Source 设成 Ext，再接 AUX 口，否则两个输出会顶在一起。
- 通过：同 0.2。
- 失败先查：Offset 是不是 Ampl 的一半；Output 开了没有。

**0.4 滑台位置和 SR2**
- 「在做什么」SR2 断电，用手轮把 X、Y 摇到行程中间、贴记号，再上电。
- 「为什么」没有限位，软件只知道"开工时在中间"这一个已知位置。
- 操作：X 摇到一端轻轻顶住，再回摇 13.5 圈；Y 第一次先数端到端圈数（行程未测），再摇到中间；KORAD 23.88 V、C.V 模式；上电后驱动器绿灯闪。
  - Y 行程：用户估计前后约 15 cm（10/13，未测），比 X 的 CXPF50（50 mm）长得多，Y 可能是别的型号。先找 Y 滑台铭牌，记下型号、行程、导程。如果导程是 2 mm，15 cm 约 75 圈，端到端摇一遍很费事；可以只摇到一端顶住，再按铭牌行程回摇一半。
- 通过：两轴各留 ≥ 10 mm 余量。
- 失败先查：C.C 灯亮 = 限流太低；红灯亮 = 驱动器报错。

## 阶段 1　离线检查模式（不碰硬件，Mac 上也能做）

**1.1 参数换算和 assert**
- 「在做什么」把 Nx、Ny、Δx、Δy 和各段速度换算成脉冲数和行数，用 assert 拦住不合法的组合。
- 「为什么」电机只认整数个脉冲；这些算错了，上硬件时不一定报错，但位置或数据会悄悄错。
- 操作：保留 B:55-74 的 assert，再加：
  - Δy / Y_UM_PER_PULSE 是整数。
  - 扫描、回程、Y 三种速度都 ≤ 4 mm/s（`MAX_SPEED_MM_S = 4`）。
  - rpb 整除 Nx；`mod(2*spr*rpb, 4096) == 0`；TRIG_RATE / rpb < 2000。
  - 累计命令位置不超过软件限位。
  - 顺便把 CH A 阻抗、TRIG IN 量程写成命名参数，运行时打印并存进 params（Rui 10/12 要求）。CH A 可选 50 Ω / 1 MΩ；TRIG IN 只有量程和耦合可设。
- 通过：打印出 K = 20、Ky = 20、fs = 248000、Nx = 10、wTrig = 2；故意设 Δx = 10.2 µm、rpb = 3 各试一次，都被拦下。
- 失败先查：B:35-36 的 UM_PER_PULSE；B:64 的取整。

**1.2 生成所有时序表并逐表检查**
- 「在做什么」生成"行扫描表"和"回程 + Y 表"，从表里反推每个触发的位置。
- 「为什么」硬件执行的就是这些矩阵，矩阵错了后面全错；矩阵对了还要靠硬件测试查 ATS 和接线。
- 操作：
  - 一个 dq 对象 6 条线：[P0.0 P0.1 P0.2 P0.3 P0.6 P0.7]，`doLines` 的顺序和矩阵列一一对应。
  - 每张表 assert：P0.6 上升沿个数（行扫描表 = Nx，回程表 = 0）；相邻两个触发之间正好 K 个脉冲；P0.7 全是 0；DIR 每次变化后至少 25 行才有 STEP；最后一行全 0。
  - 位置 assert：每行 X 去程 = 回程 = 1000 脉冲；Y 共前进 (Ny−1) × 20，最后退回同样多。
- 通过：总触发数 = 100；每行结束时 X 净位移 0，全程结束时 Y 净位移 0。
- 失败先查：DIR 在哪一行翻转；回程表开头有没有 DIR 建立时间。

**1.3 计划图和时间表**
- 「在做什么」画出 X–Y 计划路径（红点 = 触发位置）和第一个触发附近的时序放大图，并打印每张表的时长。
- 「为什么」一眼就能看出栅格方向、行顺序和起点对不对；打印的时长就是 6.10 实测时的对照值。
- 操作：参照 B:131-147 画图（注意 B:138 用到 `tr(3)`，Nx < 3 会报错）；再用 10 × 4 跑一次。
- 通过：10 × 10 等距点阵，间距 10 µm；时长约 0.37 s / 0.31 s / 6.9 s；10 × 4 画出来是"宽 10、高 4"。
- 失败先查：x、y 有没有对调。

**1.4 用假数据走一遍数据通路**
- 「在做什么」不接 ATS，造一组已知图案的 raw（第 iy 行第 ix 条的脉冲高 = iy + ix/100），走一遍存放、MAP、逐行存盘、重读。
- 「为什么」测试信号下 MAP 本来就是均匀的，数据排错了看不出来；Rui 的计划也要求先用 mock 测。
- 操作：`MAP(iy, ix) = max(v − median(v))`；每行用 `matfile` 追加写入，再 load 回来算一遍。
- 通过：MAP(3,7) = 3.07 这类值逐点对得上；重读后 `isequal(raw)` 为 true。
- 失败先查：reshape 的维度顺序；`imagesc` 的 x、y 参数。

## 阶段 2　Y 轴（照 X 轴的做法，docs/07 第 1 周 1.2）

**2.1 认出 Y 驱动器、读拨码**
- 「在做什么」断电后找到 Y 的 SR2，记下序列号，拍下 SW1–8，顺线核对 P0.2 → STEP−、P0.3 → DIR−（**10/13 晚用户已看线确认**，和 X 一样是共阳极，STEP+/DIR+ 接 +5 V；2.2 再用电确认一次）。
- 「为什么」X 的 0.5 µm/脉冲是由拨码 4000 步/转加实测得来的，Y 的拨码 SW1–8 没人看过（SW9–12 看过）。
- 操作：读 SW1–3（电流）、SW4（空闲电流）、SW5–8（细分），注意读的方向（反着读会变成 6400 步/转）；记下 P0.2/P0.3 在 BNC-2110 上是哪两个孔。
  - 同时看 Y 滑台铭牌（型号、行程、导程）。docs/01 根据电机型号推断"X/Y/Z 都是 2 mm 导程"，但 Y 行程约 15 cm（用户估计），和 X 不是同一型号，**导程和 µm/脉冲都不能沿用 X 的值**，以铭牌和 2.4 实测为准。
  - Y 台上没有装东西，水槽和托盘在 Z 上（用户 10/13）。看一眼 Y 动的时候会不会通过线缆或支架带动 Z 上的水槽。
- 通过：算出每转步数和 µm/脉冲，写进 T2 的 Y 版（第 24–25 行）后再走第一步。
- 失败先查：拨码读不清 → 第一次移动用很低的步频（约 200 Hz）。

**2.2 静态电平检查（SR2 断电）**
- 「在做什么」用 `write` 把 P0.2、P0.3 分别翻转几次，量 SR2(Y) 的 STEP−、DIR− 对地电压。
- 「为什么」先确认 P0.2 真的接到 Y、不是 Z，免得一动就把别的轴撞了。
- 操作：`d = daq("ni"); addoutput(d,"Dev1","port0/line2","Digital"); write(d,0); write(d,1); write(d,0)`；line3 同样。
- 通过：**写 0 时约 0 V 才有意义**（没接上时 STEP− 也会被光耦拉到接近 5 V）；X、Z 的 STEP− 不跟着变。
- 失败先查：端子是不是插在相邻孔。

**2.3 小步看方向**
- 「在做什么」用 T2 的 Y 版检查模式核对打印，再走 +200 µm、1 mm/s，然后走回来。
- 「为什么」确认动的是 Y，并定下 `MOVE_UM > 0` 时 Y 朝哪个方向。
- 操作：T2 另存为 Y 版，改第 21–23 行（线和方向）、第 17–18 行（距离和速度）、第 24–25 行（细分），把 `MAX_MOVE_UM` 设小；眼睛盯着三台滑台。
- 通过：只有 Y 在动；方向记进 docs/01。
- 失败先查：别的轴动了 → 立刻断电，回 2.1。

**2.4 标定 µm/脉冲 + 计数**
- 「在做什么」正反各走 3 次 ±10 mm，数手轮圈数、用卡尺量，同时用计数器数实际发出的脉冲。
- 「为什么」07 要求 Y 单独标定，不沿用 X 的换算值。
- 操作：
  - 计数：把 PFI3 的并线从 USER 1 临时挪到 P0.2（两个输出不能同时接 PFI3），T2 `COUNT_CHECK = true`；或者用 ctr2 数 Y，PFI3 一直留给 P0.6（ctr2 默认输入端子待确认）。
  - 1 mm/s 起步；记下每次卡尺读数和量的是哪个面。
- 通过：ctr = 20000；手轮正好 5 圈（如果 Y 也是 4000 步/转、2 mm 导程）；卡尺约 10.0 mm；最后回到记号。
- 失败先查：圈数不对 → 改 Y 的 µm/脉冲；计数 0 → PFI3 的线。

**2.5 速度和 C-scan 小步**
- 「在做什么」1、2、3、4 mm/s 各往返 10 mm；再连走 9 次 Δy、每次停 50 ms，最后一次退回。
- 「为什么」Y 的电流档可能和 X 不同；C-scan 里 Y 就是这样一小步一小步走，反复起停最容易丢步。
- 操作：不加速；4 mm/s 通过就停，不往上试。小步用 1.2 的"回程 + Y 表"，只留 Y 部分。
- 通过：每次手轮回到记号（±5°，约 ±28 µm）；小步 ctr = 9 × 20。
- 失败先查：声音变大、只转一点 = 失步；KORAD C.C 灯。

**2.6 收尾：接回 PFI3 + 串扰检查 + 重跑基准**
- 「在做什么」把 PFI3 接回 USER 1；ATS 不 arm、只让 Y 走一段，看 ctr1；再用 B 原样跑一次 400 条。
- 「为什么」10/7 出现过 P0.0 串进 P0.6 的情况；Y 线如果串进 P0.6，C-scan 里会多出假记录。动过接线后，要先用 B 证明链路还和以前一样。
- 操作：COUNT_CHECK 开着，只输出 Y 的移动表；然后跑 B 默认参数（检查模式 → 硬件 → 改回 false）。
- 通过：Y 单独走时 ctr1 = 0；B：ctr1 = 400、400/400、rail 0、每条 1 个沿、上升沿标准差约 2 ns；X 回到记号。
- 失败先查：ctr1 = 0（B 那一步）→ PFI3 并线没接；"Buffer 1/8 未完成" → G1 到 TRIG IN 那段松了。
