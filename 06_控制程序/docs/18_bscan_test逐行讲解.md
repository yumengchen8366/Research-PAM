```matlab
bscan.volts = (double(raw) / 65535 * 2 - 1) * ATS.inputRange_V;
```
| 步 | 写法 | 范围 | 例：raw = 40960 |
|---|---|---|---|
| 转：变成能算小数的类型 | `double(raw)` | 0 … 65535 | 40960 |
| 比：占满量程的比例 | `/ 65535` | 0 … 1 | 0.625 |
| 移：以 0 为中心 | `* 2 - 1` | −1 … +1 | 0.25 |
| 乘：乘量程 | `* ATS.inputRange_V`（4，即 ±4 V） | −4 … +4 V | **1.000 V** |

- 忘了 `double`：`uint16(40960) / 65535` 会被取整成 1，最后得到 4 V（类型还是 uint16）。
- 1 个码 = 8 / 65535 V = 0.122 mV。raw 0 → −4 V，32768 → 约 0 V，65535 → +4 V。

### (d) 10/15 改了触发频率后报错，怎么让程序跑起来

- 报错 `扫描速度 500.00 mm/s 超过上限，请降低 TRIG_RATE_HZ 或 DX_UM。`，停在第 60 行。

- 规则：**TRIG_RATE_HZ ≤ 4000 / DX_UM**。DX 5 → 800 Hz；DX 4 → 1000；DX 2 → 2000；DX 1 → 4000；DX 0.5 → 8000。
- 改法：第 24 行改回 `TRIG_RATE_HZ      = 800;`。保持 `RUN_HARDWARE = false` 先跑检查模式，看是否打印「扫描速度 4.00 mm/s，步频 8000 Hz，触发 800 Hz」。
- 100 kHz 在这个程序里做不到：那要 DX = 0.04 µm，比一步 0.5 µm 还小。要 100 kHz 就得换方案（docs/17 §4、docs/19），要和 Rui 讨论。

**第 1 行**

- 在做什么：标题。整个文件做的事：滑台匀速走，每走 5 µm 发一个触发，ATS9462 每收到一个触发就采一条 A-line。
- 语法：`%` 后面是注释，MATLAB 不执行。行首的 `%%`（后面带空格）表示一个「节」（section）的开始，编辑器里会画一条横线。光标放在某一节里按 Ctrl+Enter，只运行这一节。这个脚本后面的节要用前面算出的变量，所以平时整个运行：按 F5，或者在命令行敲 `bscan_test`。

**第 2–9 行**
```matlab
%
%  原理（全部由 Dev1 同一个硬件时钟产生，严格同步）：
%    P0.0 X STEP   ：加速 → 匀速 → 减速（→ 可选自动返回起点）
%    P0.1 X DIR    ：扫描方向，返回时翻转
%    P0.6 DAQ 触发 ：匀速段内每走 K 个脉冲（= DX_UM）发一次 → ATS9462 TRIG IN 采一条 A-line
%    P0.7 激光触发 ：与 DAQ 触发同一时刻（LASER_ENABLE = false 时不发）
%  因为触发是按"走了多少步"来发的，每条 A-line 的位置都正好间隔 DX_UM，不会出现 6.25 这类非整数关系。
%
```
- 在做什么：讲原理。四根数字线的波形都写在同一个矩阵 `do` 里（第 100–113 行）。`do` 的每一行由 Dev1 在同一个时钟节拍上一起输出（第 296 行 `readwrite`），所以 STEP 和触发严格对齐。
- 硬件：
  - P0.0 STEP：每个脉冲走一步，一步 0.5 µm。第 116 行按 `do` 里 STEP 的下降沿数步（电机实际在哪个沿走，待确认，见第 116 行）。
  - P0.1 DIR：方向线。去程是一个电平，返回时翻转。
  - P0.6：匀速段里每走 K 步发一个脉冲。现在的测试接法是 BNC-2110 USER 1 → 函数发生器外触发 → ATS9462 TRIG IN（docs/13 §1）。
  - P0.7：激光触发，和 P0.6 完全同一时刻。实物接线待核对。
- 第 8 行的意思：触发不按时间发，而是按「走了几步」发，所以 A-line 间距一定是一步（0.5 µm）的整数倍。如果触发按时间独立发，间距 = 速度 ÷ 触发频率，可能得到 6.25 µm 这种不是整数步的值，每条 A-line 的真实位置就会忽前忽后。
- 默认参数下：K = 10，一共 400 条 A-line。间距最小、最大都是 5.000 µm。第一个触发在 t = 0.1487 s，也就是加速段结束之后。

- 记法「转、比、移、乘」：

  | 步 | 写法 | 范围 |
  |---|---|---|
  | 转 | `double(raw)` | 0 … 65535 |
  | 比 | `/ 65535` | 0 … 1 |
  | 移 | `* 2 - 1` | −1 … +1 |
  | 乘 | `* ATS.inputRange_V` | −4 … +4 V |

  | raw | /65535 | ×2 | −1 | ×4 → V |
  |---|---|---|---|---|
  | 0 | 0 | 0 | −1 | −4 V |
  | 32768 | 0.5000076 | 1.0000153 | 1.526e-5 | 6.1e-5 V（几乎是 0） |
  | 40960 | 0.6250095 | 1.2500191 | 0.2500191 | 1.000 V |
  | 65535 | 1 | 2 | 1 | +4 V |

  同一个公式也可以写成 `(raw − 32767.5) / 32767.5 × 4`：「离中点差几格 ÷ 半程格数 × 量程」。正好 0 V 对应 raw 32767.5，所以没有哪个码正好是 0 V。和 SDK 官方 C 示例的公式一样（docs/05）。
- 语法：
  - **`double()` 必须加。** uint16 是整数类型，运算结果会取整：`uint16(40960)/65535` 得 1（不是 0.625），整个式子算出 4 V（类型还是 uint16）。
  - 注释 `samples x Nx`：**行是时间点，列是 A-line。** `bscan.volts(:, k)` = 所有行、第 k 列 = 第 k 条 A-line。画法见开头「先看这一段」(c)。

- 改了会怎样：公式用 `ATS.inputRange_V`，改量程（第 48 行）后自动跟着变。±2 V 时 1 个码 = 4/65535 ≈ 0.061 mV。

**本节自测**

1. 为什么 `AlazarStartCapture`（第 286 行）必须在 `readwrite`（第 296 行）前面？
   答案：`StartCapture` 之前来的触发会丢。`readwrite` 一开始就把 MATLAB 卡住 2.32 s，第一个 P0.6 在 0.1487 s 就发了。等 `readwrite` 返回再 arm，400 个触发都过去了，第 1 个 buffer 等 2 s 后报 `ApiWaitTimeout`。
2. `raw` 的第 123 列来自哪个 buffer 的第几条？
   答案：(i−1)·50 + j = 123 → i = 3、j = 23：第 3 个 buffer 的第 23 条。
3. 报错「Buffer 3/8 未完成……收到的触发数在 100 ~ 149 之间」，而「Dev1 时序输出完成。」已经打印了，说明什么？
   答案：NI 已经把 400 个 P0.6 全发了。ATS 装满了前 2 个 buffer（≥ 100 条），第 3 个没满（< 150 条），是 ATS 漏认了触发。查 P0.6 → 发生器 → TRIG IN 这一段的线和电平（10/10 就是 G1 幅度太小）。`onCleanup` 会自动清理，不会存文件。
