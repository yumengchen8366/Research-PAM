**结构应该是这样**（框架给你，插值那 3 行你自己填）：
```matlab

dt = 1 / ATS.sampleRate_Hz;
nEdge = zeros(1, Nx);
tEdge = nan(1, Nx);
for k = 1:Nx
    above = v(:,k) > th;
    nEdge(k) = nnz(diff(above) == 1);
    i = find(diff(above) == 1, 1);  % 第一个上升沿：v(i) <= th < v(i+1)
    if ~isempty(i)
        % ← 你写：用 v(i,k)、v(i+1,k)、th、dt 线性插值，
        %   tEdge(k) = 第 i 个点的时间 + 插值得到的小数部分 × dt
        %   （第 i 个点的时间是 (ATS.triggerDelay + i - 1) * dt，和 bscan.t_us 一致）
    end

fprintf('每条正好 1 个沿：%d/%d；异常的列：%s\n', nnz(nEdge == 1), Nx, mat2str(find(nEdge ~= 1)));
fprintf('上升沿 %.4f ~ %.4f us，标准差 %.2f ns，峰峰 %.2f ns\n', ...
    min(tEdge)*1e6, max(tEdge)*1e6, std(tEdge, 'omitnan')*1e9, (max(tEdge)-min(tEdge))*1e9);
```

- `nan` 加 `'omitnan'`：如果某条完全没有脉冲，不会让标准差变成 0 或报错。
- 时间用 `i - 1`，因为 MATLAB 下标从 1 开始，第 1 个点对应 t = 0。

## 为什么要接发生器背面
背面的 **AUX IN/OUT** 是发生器的**外触发输入口**。前面板的 CH1/CH2 是输出。
发生器设成 Burst + Ext 模式后，平时不出波形。背面的口每收到一个 P0.6 上升沿，它就输出 1 个周期：CH1 出一个 5 µs 方波（G1），CH2 等 2 µs 后出一个 200 ns 方波（G2）。

卡尺测位移，误差主要来自三处：**每次卡的位置和松紧不一样**、**卡尺和运动方向不平行**、**读数**。按下面的方法做，能把它们压到最小。

## 推荐做法
**1. 选一个好卡的间隙**
- 选两个**平行的平面**：一个固定（底座、电机端座或者固定在台面上的挡块），一个跟着顶板走（顶板侧面）。
- 间隙最好在 5–30 mm 之间，用**外量爪的内侧刀口**（量内径那一对）或**深度尺**都可以。哪种卡得稳就用哪种，起点和终点**必须用同一种方法、卡在同一个位置**。可以在两个面上用记号笔各点一个点，每次都卡在点上。
- 卡尺要和滑台的运动方向**平行**。歪了会读大（余弦误差），斜 5° 就差约 0.4%。

**2. 每一次读数都要"重新卡一次"**
- 松开、拿开，再重新卡上，用同样轻的力（数显卡尺推到刚接触就停，不要用力压），再读。
- 同一次卡着连读 3 遍是没用的，那只是读同一个数。重新卡才能把定位误差体现出来。

**3. 记录和计算**
| | 1 | 2 | 3 | 平均 | 极差（最大−最小） |
|---|---|---|---|---|---|
| L_start | | | | | |
| L_end | | | | | |

行程 = 平均(L_end) − 平均(L_start)。极差能告诉你这次卡得稳不稳：数显卡尺的极差在 0.02 mm 以内就算好；如果超过 0.05 mm，说明卡的位置不稳定，要换一个面重新量。

**4. 数显卡尺可以用清零**（如果是数显的）：起点卡好后按 **ZERO**，拿开卡尺；跑完再卡同一个位置，屏幕直接显示的就是差值。每个状态还是重复卡 3 次。

## 更准的办法（实验室如果有的话）
**千分表 / 百分表 + 磁力表座**：表座吸在光学平台上，表针顶住顶板侧面，**全程不拿开**。百分表分辨率 0.01 mm，千分表 0.001 mm，而且没有"重新卡"的误差，比卡尺准一个量级。注意表的量程（常见 0–10 mm）要大于 2.4 mm，表针要和运动方向平行。

## 你的问题：想检验加速，改 K 还是改速度？
**改速度，不是改 K。** 电机只关心步频：
- 步频 = K × TRIG_RATE_HZ，速度 = 步频 × 0.5 µm。
- K（= DX_UM / 0.5）只决定**每隔几步发一个触发**，不影响电机怎么动。比如 DX 5 µm × 800 Hz 和 DX 10 µm × 400 Hz，电机的运动完全一样，都是 8 kHz、4 mm/s，今天两种设置都跑过。

**有意义的加速测试：跑到不加速时会失步的速度。**
10/4 测过：不加速直接起步，5 mm/s 就会失步。`bscan_test` 有 200 µm 的线性加速（500 Hz → 目标步频）。如果加速段真的起作用，**更高的速度也应该能跑、不丢步**。这正是加速段存在的意义。

| 运行 | DX_UM | TRIG_RATE_HZ | 速度 | 步频 |
|---|---|---|---|---|
| 1 | 10 | 500 | 5 mm/s | 10 kHz |
| 2 | 10 | 600 | 6 mm/s | 12 kHz |
| 3 | 10 | 800 | 8 mm/s | 16 kHz |

- 一档一档往上加，**哪一档出现异响或位置不对就停下**。SR2 的电流只设了 0.3 A（电机额定 1.7 A），扭矩小，高速可能撑不住。
- 判断方法：`RETURN_TO_START = true`，跑前跑后用卡尺量同一个位置。回程是按同样的步数走回来的，所以只要去程或回程任何一段丢了步，**就回不到原位**。比只量单程更省事。
- 计数和采集也照常看：200/200。

**另一个旋钮：加速度本身**。加速段由 `RAMP_UM`（加速距离）和 `START_FREQ_HZ`（起步频率）决定。按现在的设置（500 Hz → 8 kHz，200 µm），速度从 0.25 mm/s 加到 4 mm/s，平均加速度约 (4² − 0.25²) / (2 × 0.2) ≈ **40 mm/s²**。把 `RAMP_UM` 改小，加速就更猛，可以试出电机能承受的极限。不过这属于下一步的优化，今天不用做。
