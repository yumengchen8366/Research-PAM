先记住三个词：

sample：采样点，某个时刻的一次数值。
record：记录，这里是一组 1024 个采样点。
buffer：缓冲区，电脑中暂存这些数据的一块内存。
本版本是：1 个 buffer 装 1 条 record，每条 record 有 1024 个 samples。

[05] 开始执行一次采集

调用下方 [10] 的采集函数。

这个函数负责准备内存、使板卡进入等待状态、等待触发、接收数据，并返回一条原始记录。

raw_u16 的名字表示：

八、DMA 是什么？“DMA 存什么数据”应当怎样理解？

DMA 全称：

Direct Memory Access，直接内存访问。

它是一种数据搬运机制。设备可以通过 DMA 将大块数据传入主机内存，避免 CPU 用软件逐个读取和复制每个采样点。

在你的程序中：

搬什么：原始 ADC 样本；
从哪里来：板卡数据通路、板卡缓存；
到哪里去：电脑 RAM 中提交给驱动的 DMA buffer；
谁安排：MATLAB 调用 SDK，驱动和硬件执行。
因此更准确的说法是：

DMA 把数据写进 buffer，buffer 保存数据。

CPU 仍然负责配置、处理完成通知、读取结果和后续计算。DMA 不意味着电脑完全不参与。

**buffer 不是某种独立硬件的名字。**它是“用来暂存数据的区域”的用途名称。板卡内有 buffer，电脑 RAM 中也可以有 buffer。

ATS9462 官方资料描述了板卡缓存和 DMA 向主机内存传输的机制，缓存用于缓解采集和传输之间的暂时差异。

一、先理解：这段代码在我们的项目里负责什么？
**它负责让 ATS9462 记录 CH A 上的一小段电压随时间变化的波形。它本身不控制激光、电机、振镜，也不生成 NI 的触发信号。**文件开头已经明确限定了这个职责。

结合你最近描述的测试，需要把两路分开：

CH A：被记录的信号。
你最近的测试中，CH A 的 BNC 线另一端没有接放大器或受控信号。正常 PAM 接收链路中，这里才应当对应你要测量的接收电压，例如放大器输出。

TRIG IN：告诉采集卡什么时候开始这一条记录。
你测试时接的是函数发生器。它提供触发条件，但这个程序并没有把 TRIG IN 的波形作为 CH A 数据保存。

TRIG IN 决定“什么时候记”；CH A 决定“记到的是什么电压”。

程序分别用 TRIG_EXTERNAL 选择触发源，用 CHANNEL_A 选择采集通道。两者不是同一个设置。
 

还要先区分三个词：

词	在这份代码里的意思
Sample，采样点	某一个采样时刻对应的一个 ADC 数字
Record，记录	一次有效触发对应的一整段波形；这里包含 1024 个点
Buffer，缓冲区	在电脑内存中接收一批数据的区域；这里恰好只装一条记录

    bufferCount = uint32(4);
    % 申请 4 块可重复使用的 DMA 缓冲区。
    % uint32 表示 32 位无符号整数，不是 ADC 的位数。

    buffers = cell(1, bufferCount);
    % 创建一个 1×4 的 cell 数组，用来保存每块 DMA 内存的引用。

    for j = 1 : bufferCount
    % 循环 4 次，分别申请 4 块 DMA 内存。

        pbuffer = AlazarAllocBuffer(boardHandle, bytesPerBuffer);
        % 用厂家分配器申请一块符合 DMA 要求的缓冲区。

        buffers(1, j) = { pbuffer };
        % 把该缓冲区的引用放到 cell 数组第 j 个位置。

    end
    % 完成 4 块缓冲区的申请。
对应原文件第 397～417 行。

1．为什么要多块内存？
这个 sample 的设计是：

板卡填充下一块缓冲区时，MATLAB 可以处理前一块已经完成的缓冲区。

因此可以交替进行传输和处理，而不是每一批都等 MATLAB 完全处理完以后才准备下一批。

原 sample 为这类多缓冲连续工作建议申请超过两块；当前选了四块。但这不代表一个只采一次的有限记录测试也必须申请四块。

为什么恰好四块？

文件没有提供针对你的电脑的性能测试依据。它是示例选择。

2．cell 和 pointer 是什么？
Cell array，元胞数组，是 MATLAB 的一种容器，这里用于保存四个缓冲区引用。

Pointer，指针，可以理解为“指向某块内存的位置引用”。pbuffer 指向 SDK 分配的内存，不是说 MATLAB 已经采到波形了。

这里要区分两件事：

buffers = cell(1, 4);
创建的是保存引用的容器。

AlazarAllocBuffer(...)
申请的才是实际用于 DMA 数据传输的内存。

3．为什么不用普通 zeros 代替？
原 sample 特别强调 DMA 缓冲区需要满足 page alignment，内存页对齐要求，并使用厂家的分配接口处理这些要求。这里的“页”是操作系统内存管理中的页，不是图像页或 PDF 页。

所以，不能仅因为一个普通 MATLAB 数组大小也等于 40960 字节，就把它当成相同的 DMA 缓冲区。

十七、核心循环：等待一个完整 buffer
逐行解释
    while ~captureDone
    % 只要结束标志仍为 false，就继续循环。

        try
        % 尝试执行本轮采集等待与处理；发生异常时进入后面的 catch。

            timeout_ms = 5000;
            % 本轮等待一个 buffer 完成的最长时间：5000 ms，即 5 秒。

            bufferIndex = mod(buffersCompleted, bufferCount) + 1;
            % 根据已完成数量，循环选择第 1、2、3、4 块缓冲区。

            pbuffer = buffers{1, bufferIndex};
            % 取得当前要等待的那块缓冲区引用。

            AlazarWaitAsyncBufferComplete(boardHandle, pbuffer, timeout_ms);
            % 等待它被完整填满，或者等待超时。
对应原文件第 507～533 行。

1．while ~captureDone 是什么？
~ 表示逻辑“非”。

所以：

while ~captureDone
就是：

只要还没有完成，就继续。

try / catch 是错误处理结构，不是另一种触发模式。

2．为什么缓冲区索引这样算？
mod(a,b) 是取余数。

当 bufferCount = 4 时：

已完成 buffersCompleted	mod(...,4)+1
0	1
1	2
2	3
3	4
4	1
5	2
因此四块内存按：

1 → 2 → 3 → 4 → 1 → 2 → …
反复使用。

这就是为什么只申请四块内存，也能完成十批 buffer。

3．为什么一次触发可能仍然超时？
因为这里等待的是：

一个完整 buffer
而这个 buffer 要包含：

10 条记录
所以只出现一次有效触发，即便对应的一条记录已经采到了，仍不等于整个 buffer 完成。

SDK 的等待接口需要等到足够的数据填满目标缓冲区。

4．为什么选择 5000 ms？
它应当长于一整个 buffer 在预期触发条件下完成所需的时间。

例如，假设被接受的触发率为 1 kHz，每个 buffer 需要 10 次触发，那么填满它所需的触发等待时间量级约为 10 ms，还要考虑记录完成与传输。

原 sample 选 5 秒作为等待上限，但没有证明这是本项目唯一合适的数值。

**延长这个时间只能允许等待更久，不能修复错误的触发源、错误的阈值或根本不存在的信号。**原注释也明确说，ApiWaitTimeout 不必然说明硬件或软件已经损坏。

因为在释放内存之前，需要结束可能仍向这些缓冲区写入的数据传输。SDK 文档也要求在退出时中止仍挂起的异步操作。

### 前几轮解释没讲到的 6 个点

1. **1024 点和 180 MS/s 是耦合的。** LabVIEW 的 ENlaser 版是 1024 点 @100 MS/s，窗口 10.24 µs。你沿用 1024 点但采样率改成 180，窗口缩到 5.69 µs，约合 8.5 mm 声程。若声波从样品到换能器的路程超过 8.5 mm，信号会落在窗口外，采到的只有噪声。[条件计算，前提：水中声速 1.5 mm/µs、延迟 0；换能器到样品的距离待确认]
2. **0.866 V 只是名义值。** 规格书给出：触发电平精度为满量程的 ±5%，迟滞 ±5%，信号幅度小于满量程 ±10% 时可能触发不可靠。按 5 V 满量程算分别约 0.25 V、0.25 V、0.5 V。所以触发脉冲应明显高于 1 V，3.3 V 或 5 V 的 TTL 没问题。你之前的 `ApiWaitTimeout`，函数发生器幅度或偏置不够是候选原因之一，尚未证实。
3. **"为什么 180"有一个能讲的理由。** 采集卡前端带宽 65 MHz，采样率至少要 130 MS/s 才能让前端通过的成分不混叠，满足的只有 160 和 180 两档。100 MS/s 的 Nyquist 是 50 MHz，而 37 MHz、58% 带宽的换能器上沿约 47.7 MHz，太贴边。同理 20 MHz 限带不能开。[条件计算，前提：当前装的是那只 37 MHz 换能器，待确认] 代价是：点数固定时窗口变短，数据量变大。
4. **MATLAB 封装函数失败时抛异常。** 官方 Getting Started 明写："MATLAB functions do not return error codes, instead, they throw exceptions"。所以脚本不接返回值是官方用法。但 `AlazarWaitAsyncBufferComplete.m` 对超时是否特殊处理，网上找不到源码，要在实验室电脑打开确认。
5. **只提交 1 个 DMA buffer 没被官方背书。** 文档说应用至少应提供两个 buffer，官方 sample 用 4 个。单条采集用 1 个大概率可行，但脚本从没在真机跑通过。若在 Post 或 Wait 处报的不是超时，先怀疑这里。
6. **文件名带空格和括号，MATLAB 不能运行。** `ats9462_aline_test (1).m` 要先改名，例如 `ats9462_aline_test_v2.m`。Downloads 里还有一个不带你注释的旧版同名文件，别跑错。

### 仍然不能当已知讲的

- 当前装的是哪只换能器；放大器型号、增益和要求的负载。
- TRIG IN 上实际信号的高低电平。
- 板卡型号（你账本里的冲突 #6）。脚本第 133 行的 16-bit 检查如果通过，就不支持 12-bit 的 ATS9350 这一说法。
