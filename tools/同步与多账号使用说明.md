# PAM 同步与多账号使用说明

> 2026-10-04 建。目标：两个 Claude 账号 × 三个地方（Mac / 实验室 CAOLAB1 / claude.ai 网页）都能接着做 PAM，进度不丢。

## 0 先弄清：什么会跟着走，什么不会

| 东西 | 存在哪 | 换 Claude 账号会跟过去吗 | 本方案怎么处理 |
|---|---|---|---|
| Claude Code 对话原文 | 本机 `~/.claude/projects/<路径>/*.jsonl` | ❌（同一台电脑同一个系统用户下文件还在，但新账号的桌面版侧边栏不一定列出来） | 导出成 Markdown → `08_对话记录/` |
| Claude Code 记忆 | 本机 `~/.claude/projects/<路径>/memory/` | ❌ 不跨电脑 | 重要事实写进 docs / master；旧记忆备份在 `08_对话记录/claude-memory/` |
| 项目规则 | 仓库 `CLAUDE.md` | ✅ 随仓库走 | 任何账号打开这个文件夹都会自动读 |
| skill `research-progress` | 仓库 `.claude/skills/` | ✅（Claude Code）；网页要另外上传 | 网页上传 `tools/claudeai_upload/research-progress.zip` |
| claude.ai 网页对话（含 Project「cao meeting」） | Anthropic 服务器，绑旧账号 | ❌ 没有账号间迁移功能 | 旧账号「导出数据」→ `tools/import_claudeai_export.py` 转成 Markdown |
| 网页 Project 设置和知识文件 | 绑账号 | ❌ | 新账号新建 Project，说明用 `02_笔记与上下文/project-instructions.md`，知识连 GitHub 仓库 |
| 连接器（Google Drive 等）授权、Settings | 绑账号/本机 | ❌ | 新账号里重新点一遍 |

**核心规则：仓库是唯一真相。** 对话是过程，文件是结果；结论只写在对话里等于没写。

## 1 一次性：建 GitHub 私有仓库（在 Mac 上，约 5 分钟）

本仓库已经在 Mac 上 `git init` 并做了第一次提交，还没推到 GitHub。

```bash
brew install gh
gh auth login          # 选 GitHub.com → HTTPS → Login with a web browser，按提示在浏览器里授权
cd ~/Research-PAM
gh repo create Research-PAM --private --source . --push
```
推完后在 github.com 上确认仓库是 **Private**。

> 仓库里有实验室的数据、导师会谈记录、联系人表。只用 Private，不要加 collaborator，不要改成 Public。
> 实验室的 LabVIEW 原工程和录音没有进 git（见 `.gitignore`）。

## 2 Mac 上用新账号

1. Claude 桌面版 → 左下角头像 → 退出登录 → 用新账号登录。（也可以在终端里 `claude` → `/login`。）
2. Code 标签页 → 打开文件夹 `~/Research-PAM`。
3. 第一句话可以直接说：「按 CLAUDE.md 开工」。它会 `git pull`、读工作日志最后 3 条。
4. 收工时说：「按 CLAUDE.md 收工」。它会写工作日志 → 导出这次对话 → commit → push。

说明：同一台 Mac、同一个系统用户下，`~/.claude/` 里的旧会话和记忆文件都还在，与登录哪个账号无关；但旧账号的会话**不保证出现在新账号的侧边栏**（待确认）。不用纠结这个——旧对话全文都在 `08_对话记录/` 里，新会话直接 grep 就能查到。

## 3 实验室电脑 CAOLAB1（Windows）首次接入

实验室电脑上的 `Desktop\PAM_controlProgram` 和 `Desktop\Matlab` 比仓库里的版本**更新**（仓库里是 10/3 19:34 的快照，10/4 电机实验的结果还没进来）。第一次接入要把这部分合并进来。

### 3.1 装 Git 并登录 GitHub（一次）
1. 装 Git for Windows：https://git-scm.com/download/win （默认选项即可；它自带 Git Credential Manager）。
2. 这是实验室公用电脑：GitHub 登录建议用 **fine-grained personal access token**，只授权 `Research-PAM` 这一个仓库、权限 Contents = Read and write、设到期日。第一次 push 时弹窗里粘贴这个 token。离开实验室或换人用时，在 Windows「凭据管理器」里删掉 github.com 那一条。
3. PowerShell：
   ```powershell
   cd $env:USERPROFILE\Desktop
   git clone https://github.com/<你的用户名>/Research-PAM.git
   git -C Research-PAM config core.quotepath false
   ```

### 3.2 合并 10/3 之后的进度（一次）
在实验室电脑的 Claude Code（哪个账号都行）里打开 `Desktop\Research-PAM`，把下面这段整段发给它：

> 这是 PAM 仓库第一次在实验室电脑上接入。请按顺序做，每步做完告诉我结果，**不要删除任何旧文件**：
> 1. 对比 `Desktop\PAM_controlProgram\docs\` 和仓库 `06_控制程序\docs\`、`Desktop\Matlab\` 和 `07_MATLAB\`、`Desktop\System_test_09_25\` 和 `07_MATLAB\System_test_09_25\`：列出实验室这边更新或新增的文件（按修改时间和内容）。
> 2. 我确认后，把这些更新复制进仓库对应位置（`PAM_controlProgram\CLAUDE.md` 不要覆盖 `06_控制程序\CLAUDE.md`，只把新增的规则合并进去，路径保持仓库内路径）。
> 3. 把 `Desktop\PAM_controlProgram\LabviewPAM\` 复制到 `06_控制程序\LabviewPAM\`（已被 .gitignore 排除，只在本机）。
> 4. 导出本机 PAM 会话：`python tools\export_pam_chats.py --list`，然后对 10/3 晚之后的 PAM 会话用 `--ids ... --machine "LabPC(旧账号)"` 导出（10/3 之前的仓库里已有，同 id 重导会覆盖成最新版，可以全部重导）。
> 5. 在 `06_控制程序\docs\工作日志.md` 末尾加一条“仓库接入”，然后 `git add -A`、commit、push。

### 3.3 以后在实验室
- Claude Code 打开 `Desktop\Research-PAM`（不再用 `Desktop\PAM_controlProgram`）。
- MATLAB 的当前文件夹设成 `Desktop\Research-PAM\07_MATLAB`，脚本用 `pwd` 存数据，所以 `aline_data\` 会直接落在仓库里。
- 旧的 `Desktop\PAM_controlProgram`、`Desktop\Matlab` 先留着别删，用一两周确认没问题再处理。

## 4 claude.ai 网页（新账号）

1. **上传 skill**：Settings → Capabilities（或 Skills）→ Upload skill → 选 `tools/claudeai_upload/research-progress.zip`。
2. **建 Project**「UV-PAM」：
   - Set instructions：粘贴 `02_笔记与上下文/project-instructions.md` 全文。
   - Add content → GitHub → 授权 GitHub → 选 `Research-PAM` 仓库 → 勾选这些（别全选，太大）：
     `CLAUDE.md`、`02_笔记与上下文/UV-PAM-master.md`、`02_笔记与上下文/context-conflicts.md`、`02_笔记与上下文/meeting-prep/`、`06_控制程序/docs/`、`08_对话记录/INDEX.md`。需要时再加某一份对话记录或会谈记录。
   - 仓库更新后，在 Project 里点 GitHub 那一项的同步按钮，网页拿到的才是最新版本。
3. 网页里不能写文件：每次聊完让它列「需要写回仓库」清单，回 Claude Code 里写入并 push。
4. 手机 App 登录同一个新账号就能用这个 Project。

## 5 把旧账号的网页对话搬过来（一次）

1. 旧账号 claude.ai → Settings → Privacy → **Export data**。邮件里的下载链接有时效，收到就下载。
2. 解压到比如 `~/Downloads/claude_export_old/`。
3. 在 Mac 的 Claude Code 里（仓库根目录）：
   ```bash
   python3 tools/import_claudeai_export.py ~/Downloads/claude_export_old --list
   python3 tools/import_claudeai_export.py ~/Downloads/claude_export_old --project "cao meeting"
   python3 tools/import_claudeai_export.py ~/Downloads/claude_export_old --keyword PAM Rui ATS9462 LabVIEW 光声 导师 A-line
   python3 tools/export_pam_chats.py --reindex
   ```
   先用 `--list` 看一遍，八字/奇门这类个人对话不要导进来（关键词过滤后再检查 `08_对话记录/网页/`，不想要的删掉再 commit）。
4. 导出 zip 里是**全部**对话（含私人内容），用完把它从 Downloads 删掉，别放进仓库。

## 6 每天怎么用（两个账号都一样）

| 时刻 | 做什么 |
|---|---|
| 开工 | Claude Code 打开仓库 →「按 CLAUDE.md 开工」（= `git pull` + 读工作日志最后 3 条） |
| 中途 | 一个窗口只做一个模块；确认的事实当场写进 docs |
| 收工 | 「按 CLAUDE.md 收工」（= 写工作日志 → 导出本次对话 → commit → push） |
| 换地方前 | 确认上一处已经 push（`git status` 干净、`git log origin/main..` 为空） |

**防冲突**：同一时间只在一个地方改同一个文件。push 被拒 → `git pull --rebase` → 有冲突就停，让 Claude 逐段对比后再合并，别直接选“用我的版本”。

**会前（周四晚前）**：网页 Project 或 Mac 上用 `research-progress` skill 写 `02_笔记与上下文/meeting-prep/<周一日期>.md`。**会后**：只改 master §19、§20（先同意再写），工作日志记一条。

## 7 出问题时

| 情况 | 办法 |
|---|---|
| 新账号的 Claude 不知道之前的事 | 让它读 `06_控制程序/docs/工作日志.md`、`08_对话记录/INDEX.md`，再 grep 关键词 |
| 忘了导出某次对话 | 在那台电脑上 `python3 tools/export_pam_chats.py --list` 找 id，再 `--ids` 导出，push |
| 网页 Project 里看到的是旧内容 | Project 里点 GitHub 同步；确认 Code 那边已 push |
| 两台电脑改了同一个文件 | `git pull --rebase` 报冲突时停下，让 Claude 逐段对比合并 |
| 误把大文件 commit 了 | 别 push；`git reset --soft HEAD~1`，把文件加进 `.gitignore` 再提交 |
